### 5.4 拨号重试严格契约改由 retry 单测钉住
macOS CI 观察到 accept=4（期望 5）——是指标失效（假代理 accept 后立即 close，客户端可能在对端 accept 前收到 RST）。新增 `exponential_backoff_attempts_exactly_n_times` 断言恰好 5 次调用；client.rs 用例改为断言「确实重试过」并说明 strict 契约所在。

## 14. 【根因】inbound 监听静默死亡 → CF 521 / 节点 -1（11:30-12:10）

### 14.1 现象与生产级复现
用户节点测试截图：所有 `-cdn` 节点 -1，`-argo` 与直连正常。CF 侧直查 `home.begonia92.top` 返回 **HTTP 403 `error code: 1034`**（隧道/DNS 路由层，用户自述是其侧问题），而回源到源站 :443 得到 **connection refused → 521**。

逐台核查发现 **8 号机 :443 无人监听**（其余 25 个 inbound 正常，进程 active，日志零线索）。**2 步复现**：
```python
ctx = ssl.create_default_context(); ctx.check_hostname=False; ctx.verify_mode=ssl.CERT_NONE
ctx.set_alpn_protocols(['http/1.1'])
raw.connect((origin, 443)); t = ctx.wrap_socket(raw, server_hostname='home.begonia92.top')  # TLS 握手成功
t.close()                                                                                   # 握手后断开 → :443 监听消失（11 秒内）
```
对照：仅「裸连即断（不发 TLS）」→ 监听存活。**必须完成 TLS 握手再断开才触发。**

### 14.2 根因（逐环核对到依赖源码）
`crates/xray-transport-websocket/src/register.rs:133`
```rust
if msg.contains("closed") { break; }   // ← 用错误文本决定生死
```
错误链：rustls `Error::PeerClosed`（Display = "peer closed connection without sending TLS alert"，**含小写 closed**）→ tokio-rustls 以 `io::Error(InvalidData, err)` 透传（Display 即 rustls 原文）→ tungstenite 包成 `Error::Io` → 本仓 `WsError::Tungstenite` → 文本命中 `contains("closed")` → **整个 accept 循环 break** → `WsListener` 被 drop → `TcpListener` 关闭 → 端口不再 listen，而 **break 分支不打任何日志**（静默死亡）。
同源文本：tungstenite `ConnectionClosed` = "Connection closed normally"。h2 分支返回 "http/2 request rejected"（不含 closed）安全。

同款写法共 3 处 + 同族 1 处：tcp(hub.rs:128) / unix(hub.rs:279) 同样 `contains("closed")`；hysteria(register.rs:124) 为 `Err(_)=>break`（任何 accept 错误都杀监听）。**已核安全**：quic(quinn accept 只返 None)、splithttp/xhttp-h3、hysteria-h3、grpc(按 `ErrorKind` 判 EMFILE + 退避 = 全仓最正确样板)、grpc-h2、httpupgrade。

### 14.3 影响面（按传输，不按协议）
ws 循环承载 vless/vmess/trojan/ss-ws（443/2083/2096/39003…）：**同一循环，一次只死一个端口**；443 是 CF 回源口 → 它一死 = 所有 `-cdn` 节点全灭。reality/trojan-tls 走 tcp 循环（同行），hysteria 走第三种写法。

### 14.4 处置
- 缓解：三台装 `/usr/local/bin/p443-watch-v2.sh` + cron（每分钟检测 443 → 抓现场快照 `/root/agsbx/443-death/`（fd/线程/conntrack/dmesg/剩余监听/最近日志）→ 自动 restart）。已实测有效：11:49:01 抓现场 → 拉起 → 443 恢复。
- 修复：派单把 4 处 accept 循环改为**按错误类型判断、错误文本永不作为退出条件、只有显式 close 才退出、意外退出打 error 级日志**（用户明确要求"发现 443 跪了就写日志"），并补回归单测（错误文本含 closed 的单连接级错误 → 动作为"继续"）。
- 验收：修复版灰度 8 号机 → 用上述 2 步杀手客户端打 5 次 → 监听必须存活（当前会死）→ 再推 176/104 → 撤看门狗。
