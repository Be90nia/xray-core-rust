## 结论

**VERDICT: PASS（票面前提修正型交付）** — QUIC 路径 UDP GSO 在 Linux 上**本就默认启用**（quinn-udp 0.5.15 构造期探测 UDP_SEGMENT），票面"quinn-udp 0.6 无 GSO API、需自实现"的前提不成立。实际落地：Go parity 禁用开关（`disableGSO`）+ quinn 官方抽象 socket 注入点薄包装 + 启用/回退/分段边界三类测试，双床（Windows 18/18 + Linux Docker 19/19）全绿。recoverable 偏差一项（票面版本号与 GSO 缺失判定，见下）。

## 票面修正（考古实锤）

| 票面声称 | 实况（一手源码） |
|---|---|
| quinn-udp 0.6，无 GSO API | **quinn-udp 0.5.15**（quinn 0.11.11 锁定，Cargo.lock:3288） |
| quinn 0.11 未开 GSO | `UdpSocketState::new` 构造期探测：内核 ≥4.18 且 `setsockopt(UDP_SEGMENT)` 成功 → `max_gso_segments = 64`（unix.rs:817-841）；失败 → 1（**优雅回退非 panic**）；运行中 sendmsg EINVAL 自动降级（unix.rs:352-359） |
| 需自实现 UdpSender / socket 层包装 | 仅**禁用**路径需包装；启用路径 = quinn 默认路径零改动 |

同仓 `docs/research-transport-stack-2026-09-15b.md:83` 亦独立记载 "quinn-udp 0.5 已默认开 sendmmsg/GSO/POLL_FIRST"，与本次考古一致。

## 方案

- **开关**：`QuicConfig.disable_gso` ← JSON 键 `disableGSO`（Go `QuicParams.disableGSO` parity，config.proto:81 / dialer.go:142）。默认 `false` = GSO 启用（= 现状默认路径）。
- **禁用接线**：quinn tokio socket 实现为私有类型，唯一公共注入点 `Runtime::wrap_udp_socket → Arc<dyn AsyncUdpSocket>` + `Endpoint::new_with_abstract_socket`。`NoGsoSocket` 薄包装把 `max_transmit_segments()` 钳到 1（quinn 发送端不产生多段 Transmit → 不打 UDP_SEGMENT cmsg），其余方法全转发。
- **接收侧 GRO 保留**（`max_receive_segments` 转发），与 quic-go `DisableGSO` 只关发送的语义一致。
- **无 cfg 分叉**：包装全平台无副作用（非 Linux 平台 `max_transmit_segments` 本就为 1）；仅 GSO 探测断言测试 cfg(linux) 门控。
- **分段安全**：多段打包/stride 递进由 quinn/quinn-udp 内部处理，本模块不碰 Transmit 内容（记忆铁律"遍历按 stride 递进否则死循环"对应逻辑在上游，已被 echo 边界测试覆盖）。
