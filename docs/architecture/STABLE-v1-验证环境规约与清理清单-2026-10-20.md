## 1. 硬边界（违反即事故）

### 1.0 【最高优先级】用户配置文件 —— 绝对只读

> **用户 2026-10-20 明确指示**：「可以拿来测试..但是不要动我的配置文件就好」

| 禁改对象 | 路径 | 处置 |
|---|---|---|
| **生产 xray 配置** | `/root/agsbx/xr.json` | **只读**。任何情况下不得编辑/覆盖/移动/重命名/删除 |
| **生产 xray 二进制** | `/root/agsbx/xray` | **只读**，不替换、不改名 |
| **agsbx 整个目录** | `/root/agsbx/**` | **只读**。测试产物一律不得写入此目录 |
| 其余生产配置 | `/root/*.json`、`/etc/sing-box*`、`/etc/cloudflared*`、`/root/.cloudflared*` 等 | **只读** |

**规则**：
1. **测试配置一律新建在隔离目录** `/tmp/xray-stable-<ts>/conf/`，**绝不复用/覆盖生产配置**。
2. 需要「与生产同配置」做对照时 → **只 `cat`/`diff` 读取**，**内容不外传、不落盘到本机、不在报告中贴出敏感内容**（凭据/UUID/域名一律打码）。
3. 生产进程**不重启、不 reload、不 signal**（`kill -HUP` 等一律禁）。
4. 若测试误碰生产配置 → **立即停止一切操作**、先报告用户，再谈恢复；**不得自行尝试"修好"**（避免二次破坏）。

## 3. 各验证项的具体做法（只列环境相关部分）

| 项 | 环境 | 做法 | 关键判定 |
|---|---|---|---|
| **A2** WFP 泄漏过滤 | Windows 本机 | `pktmon` 抓**物理网卡**（非 loopback），`pktmon filter add -p <测试端口>`；TUN 建好后触发一次 DNS 查询 | 物理网卡上**看不到**该 DNS 包 = 泄漏已拦；**看得到 = 未拦住**（回归） |
| **A3** 自动系统路由表 | 176 | `ip route show` 前后对比；`ip rule` 检查策略路由；测完精确删自己加的条目 | 路由表出现指向 TUN 设备的条目；流量 `ip route get <dst>` 命中 TUN |
| **A4** 系统 DNS 接管 + dns_skip | 176 | 改 `resolv.conf` 指向测试 DNS；`tcpdump -i any port 53` 看是否绕回；测完**恢复原 resolv.conf**（先备份） | 无查询绕回隧道造成环路；无 DNS 查询死锁 |
| **A5** xmc 互通 | 176 | Go server（用生产机**之外**的独立进程/端口）↔ Rust client，双向抓包比对 | 双向握手完成，无「not white-listed」断连 |
| **A6** policy 零缓冲/EOF | 176 | 独立端口跑 VMess 零缓冲 + 优雅关闭，抓包 + 客户端读 EOF | 大包不丢；关闭后客户端读到 EOF（非超时/非 RST） |
| **A7** WG 数据面 | 176 | 独立端口 WG 隧道转发 1MB TCP + IPv6 + UDP，校验回显 | 载荷**真的过隧道**（非仅握手） |
| **B3** 嗅探 e2e | 176 或本机 | HTTP 代理 → TLS 嗅探 → 按域名改投；抓包看 SNI | 路由命中**嗅探出的域名**而非 IP |
| **A0/proto** pb+API 双向 | 176 | Go 与 Rust 各起独立实例，用 `.pb` 配置 + gRPC AddOutbound/AlterInbound 互操作 | 无解码报错、无静默错值 |

**通用要求**：每个验证项**必须**附「抓包/命令输出 + 期望值 + 实际值」三件套（沿用项目三查纪律：Consistency grep 对齐 / Scope diff 匹配 / Verification 三件套）。

## 4. 清理清单（每项验证后立即执行，不攒到最后）

### 4.1 176

```bash
# 0) 收尾前自检：只杀自己起的（cmdline 含工作区路径）
ps -eo pid,cmd | grep '/tmp/xray-stable-' | grep -v grep

# 1) 停自己的进程（先 SIGTERM，5s 后仍存活才 SIGKILL）
for p in $(ps -eo pid,cmd | grep '/tmp/xray-stable-' | grep -v grep | awk '{print $1}'); do
  kill $p 2>/dev/null; done
sleep 5
for p in $(ps -eo pid,cmd | grep '/tmp/xray-stable-' | grep -v grep | awk '{print $1}'); do
  kill -9 $p 2>/dev/null; done

# 2) 删工作区（含抓包/证书/二进制）
rm -rf /tmp/xray-stable-<ts>

# 3) 删自己加的路由/规则（若有）
ip route del <自己加的条目> 2>/dev/null
ip rule del <自己加的条目> 2>/dev/null

# 4) 恢复 resolv.conf（若改过）
cp /tmp/resolv.conf.bak-<ts> /etc/resolv.conf
rm -f /tmp/resolv.conf.bak-<ts>

# 5) 验证：生产进程/端口完好 + 无残留
ps -p 470,456,434,847,769 -o pid,cmd --no-headers   # 应全部还在
ss -tlnp | grep -E '3900[0-9]|3901[0-6]|2053|39949|39761|39804|20241'   # 应仍是原 pid
ls -d /tmp/xray-stable-* 2>/dev/null               # 应为空
df -h / | tail -1                                  # 剩余应回到 ≈2.0G
```

**清理验收（不通过不算测完）**：
1. `ps -p 470,456,434,847,769` → 五个生产进程**全在**
2. `ss -tlnp` 中生产端口的 PID **与基线快照一致**（470/456/434/847/769）
3. `ls -d /tmp/xray-stable-*` → 空
4. `df -h /` → 剩余回到基线（≈2.0G）
5. `ss -tlnp` 中**无** 12829-12899 段的监听

## 5. 事故预案

| 事故 | 立即动作 |
|---|---|
| 误杀生产 xray（pid 470） | `ps -p 470` 确认；若已死，**用原命令重启**：`/root/agsbx/xray run -c /root/agsbx/xr.json`（用 `nohup` + `setsid` 脱离 ssh 会话）；立即告知用户 |
| 改坏 `resolv.conf` | 从备份恢复（步骤 4.1-4）；若无备份 → `nameserver 223.5.5.5` + `nameserver 119.29.29.29` 临时兜底并告知用户 |
| 加错 iptables/ip rule 致断网 | `iptables -S` / `ip rule show` 快照回滚；**先删自己带标记的条目**再告知用户 |
| 磁盘写满（剩 2.0G） | 立即删 `/tmp/xray-stable-*` 抓包文件；`df -h /` 复核 |
| 端口冲突 | `ss -tlnp` 查占用，换 12829+ 下一个端口，**不 kill 占用者** |
| 抓包文件含隐私流量 | 抓包只在测试窗口开启 + `pktmon filter` 仅加测试端口；测完立即删 |
