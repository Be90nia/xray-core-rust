# Xray-core-rust 池化蓝图 —— 双池互喂理念推向热路径（2026-11-02）

> 提案人：用户（口供"其实 inbound outbound DNS..这些都可以仿照双池互喂的理念来做改造"）
> 地基：udf-frame `skeleton-infra::pooled_thread_pool::PooledThreadPool<T>`（MemoryPool × ThreadPool 互喂，
> 借还 RAII / panic 也归还 / 拒绝计数留痕 / borrow_timeout 构造期必填）
> 验收门：loopback ≥154 MB/s（历史锚 154-167，2026-11-02 实测新内核仅 125，-20%）、alloc/MB 回 2.15/2.22

## 0. 理念

双池互喂的精髓 = **资源与执行者解耦**：worker/任务不拥有缓冲，缓冲不绑定连接；
用时借、Drop 还（RAII）；借空 = 显式丢弃 + 计数（非静默）。
udf 已给全零件：`MemoryPool`（借还上限）、`ThreadPool`（零自旋/优雅缩容）、
`PoolBase`（水位/审计/记账）、`PooledThreadPool`（两者组合的时序封装）。

**先例已在主仓（冷路径）**：`GeodataLoadPool`（app-geodata/loader.rs）、
`RouterBuildPool`（app-router/condition.rs）都已是 `PooledThreadPool<Vec<u8>>`。
本蓝图 = 同一模式推向热路径。

## 2. 四子系统双池互喂形态（用户提案映射）

| 子系统 | 互喂两池 | 形态 |
|---|---|---|
| **Mux** | worker 池 × 帧缓冲池 | 帧任务入队 → worker 认领 → 借 buffer 写帧 → 发送 → Drop 还池 |
| **outbound** | 拨号任务 × 连接池（preconnect 重生） | 拨号请求入队 → 连接池认领补拨 → 会话消费 → virgin-only 判定还池/关 |
| **inbound** | accept 槽 × 读缓冲池 | accept → 借读缓冲（read_multi_buffer 从池取）→ 会话关闭还 |
| **DNS** | 查询任务 × 上游连接池+缓冲 | 查询入队 → 上游连接池取连 → 查询缓冲借还 |

## 3. 分阶段路线

- **P0 倒退修复（进行中，bd 性能倒退票）**：ws 池缺省回 12（已改，bccece82 已构建）；
  bridge.rs `Budget::tokio().deadline().timeout(read)` 三层包装审计——数据面每读过三道组合器，
  loopback -20% 头号嫌疑；spawn_reaping 36 站点托管开销核查。
  验收：loopback 回 154+，用户实测 cdn+argo/直连恢复昨日基线（50-60 / 27+）。
- **P1 热路径缓冲统一**：sniffer/DNS/udp_session/bridge/mux/ws 的裸分配逐站迁
  `XrayBufPool`（xray-frame，已走 PoolBase）/udf MemoryPool；每站过 alloc/MB 门。
- **P2 连接池骨架上浮 udf**：从 WsConnectionPool/QuinnConnectionPool 提炼
  `AsyncResourcePool`（补拨/水位/TTL/per-key/借还计数，全泛型零 xray 类型，走 §3.5.4 回路：
  独立 PR + udf 三平台 CI 绿 + 主仓换依赖删副本）；virgin-only/握手 key 留主仓特化。
- **P3 Mux 双池互喂**：帧缓冲入 MemoryPool，worker 认领时借（对齐 PooledThreadPool 时序封装语义，
  panic unwind 归还路径照抄其测试钉法）。

## 4. 纪律挂钩

- 每步走"新功能长在框架上"（CLAUDE.md §3.5.3）：机制进 udf-frame / xray-frame，协议 crate 只留薄适配。
- 提炼判据：骨架零 xray 类型（全泛型 + 工厂 trait）；连接语义（virgin-only）是网络方向件，留主仓。
- 池上界必须显式（borrow_timeout/容量构造期必填，D21 同源）；借空 = 丢弃 + 计数，禁静默无限等。
