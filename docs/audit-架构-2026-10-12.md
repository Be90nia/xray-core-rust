## 2. 抽象层稳定性

### 2.1 Reader/Writer trait（master 现状）

```rust
// crates/xray-buf/src/io.rs:74-78
pub trait Reader: Send {
    fn read_multi_buffer(
        &mut self,
    ) -> Pin<Box<dyn Future<Output = Result<MultiBuffer>> + Send + '_>>;
}
```

- **架构状态**：master 持 reverted 形态（`d820547f` 把 `f242e67b` poll 化回退），trait 仍返回 `Pin<Box<dyn Future>>`
- **每读/写 1 次堆分配**——dispatcher 装饰链（SizeStat/Cached/EndpointOverride）× N 层即 N 次装箱
- 已被 perf 报告登记为 **AUDIT-PERF-001（xi40 第 4 条）**，本审计不重复立项
- 修复分支 `feature/framework`（f242e67b）已含 poll trait + 具名 future 默认方法范式

→ 抽象**契约稳定**（trait 不变）；实现策略分两条路径（master 装箱 vs branch poll）；分支形态要 gate 才能进 master。

### 2.2 Connection / Listener / Dialer

```rust
// crates/xray-transport/src/connection.rs:30-40
pub trait Connection: AsyncRead + AsyncWrite + Send + Sync + Unpin {
    fn remote_addr(&self) -> io::Result<Option<SocketAddr>>;
    fn local_addr(&self) -> io::Result<Option<SocketAddr>>;
    fn close_read(&mut self) -> io::Result<()> { ... default Unsupported ... }
    fn close_write(&mut self) -> io::Result<()> { ... default Unsupported ... }
    fn raw_tcp_clone(&self) -> Option<TcpStream> { None }
    fn is_raw_tcp(&self) -> bool { false }
}
// crates/xray-transport/src/listener.rs:18-22
pub trait Listener: Send + Sync {
    fn accept<'a>(&'a self) -> Pin<Box<dyn Future<Output = io::Result<Box<dyn Connection>>> + Send + 'a>>;
    fn local_addr(&self) -> io::Result<SocketAddr>;
}
```

- **契约稳定**：default 方法（close_read/close_write/raw_tcp_clone/is_raw_tcp）正确降级（Unsupported / None / false），TLS/REALITY/transport 包装层选择性覆写
- **形态正确**：supertrait 约束 `AsyncRead + AsyncWrite + Unpin + Send + Sync`，`Box<dyn Connection>` blanket impl 由 tokio 自动派生
- **唯一债务**：`accept()` 返回 `Pin<Box<dyn Future>>` 与 §2.2 坑 7 同源（trait 装箱放大）——但这是 listener 边界，trait 上每接受 1 连接的固定成本，不像装饰链 N 层放大

→ 抽象层**设计良好**，与 oracle-framing-arch §2 数据面裁决一致。**未触发债务**。

### 2.3 DispatchHandler / OutboundHandlerManager / RoutingRouter（dispatcher 抽象）

- **trait 集合稳定**，14 个实现方遍布 proxy-vless/vmess/ss/trojan/blackhole/freedom/loopback/mux/transport-naive/trojan/tuic/tun/wireguard（grep `impl DispatchHandler for` 50+ 处）
- **未现稳定性债务**——但 trait 集合是否「完整冻结」需 §4 P4 API 转正门槛审查（§6.1.3）

### 2.4 Feature / Factory trait（注册机制）

```rust
// crates/xray-features/src/registry.rs
pub type FeatureFactory = Arc<dyn Fn(&[u8]) -> Result<Arc<dyn Feature>> + Send + Sync + 'static>;
static REGISTRY: OnceLock<RwLock<HashMap<&'static str, FeatureFactory>>>;
```

- **当前形态**：全局 HashMap + Arc<dyn Fn> 工厂闭包——**与架构 §1.0.2 FactoryRegistry 概念不直接对位**
- 架构 §1.0.2 承诺 FactoryRegistry = 「显式注册 + tag 选择 + BuildCtx + 中央 match 臂退化为零逻辑注册行」——**当前 xray-core/src/outbound.rs:672 中央 match 臂仍是手工构造（5814 行文件内嵌 7 个 parse 函数）**
- **未落地**：FactoryRegistry trait + BuildCtx 显式化（规划 P2.0）

→ 注册表机制在但**未达宪法承诺的形态**。

### 5.2 feature/framework 起点 f242e67b 的代码质量

commit `f242e67bd936a1dabf3845da7bd8b57fc0e574df` (2026-10-12 00:01:25) 标题：

- 价值：让 blackhole 在 feature/framework 分支升级 io.rs poll 化时**零障碍**
- **代码质量**：✅ 一处 net change + 注释解释 P1 漏网原因；不扩大 P1 范围；不重写 blackhole 主流程

→ f242e67b 是**典型收口补丁**（小、纯、就事论事），但揭示了一个**结构性问题**：P1 io.rs poll 化（f242e67b 全集）**在 master 是被回退状态**（d820547f 「p1 io.rs poll 化全家回退」），只有 buffer 内存优化收益留 master——完整 poll 化形态仅在 feature/framework 分支存在。**架构收益不进 master 的模式**是后续 P1→master 的主要摩擦点。

`tools/check_dep_tiers.py` + `docs/refs/dep-tier-waivers.md` + `Cargo.toml [workspace.lints]` + `cargo-deny bans` 是**架构纪律的执法点**。任一缺位都让 ARCHITECTURE.md §6.4 承诺字面失效。优先顺序：

五件套承诺字面缺位是 P2.5 vmess 首迁的最大风险（vmess duplex + UDP + join 全塌缩进引擎时若 ctx.event/tuning 没有，所有事件/参数都得现场打补丁）。建议在 P2.0 落地后**先实现五件套最小版**（仅覆盖 vmess 首迁需要的方法）再启动 P2.5。
