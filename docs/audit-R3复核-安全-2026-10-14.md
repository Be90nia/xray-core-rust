## 二、逐条独立验证

### 声明 1 —— xmc 握手超时缺失【修正：实质证实】

**独立验证方法**：先读声明所指 `finalmask/mod.rs:40-90 raw` 核引用，再 grep 全 finalmask 目录定位真实 spawn 点，再 grep `timeout|Deadline|deadline|sleep` 扫超时原语，最后读 Go deadline.go/server.go/client.go 原文。

- `finalmask/mod.rs:57-61` 实为 `PACKET_QUEUE_CAP` 常量（:57）与 `AsyncIo` trait 文档区——**无任何 tokio::spawn**。该文件真正的 spawn 在 :449-450 / :467-468（PacketIoConn UDP driver/worker，与 xmc 无关）。
- xmc 真实 spawn 点：`crates/xray-transport/src/finalmask/xmc/mod.rs:51`（`wrap_conn_client`）与 `:58`（`wrap_conn_server`）——`tokio::spawn(conn::tcp_bridge(raw, server, …))` fire-and-forget，duplex 缓冲 `UDP_SIZE*2`（mod.rs:49,56）。
- **全 xmc 模块零超时原语**：grep `timeout|Deadline|deadline|sleep` 于 `crates/xray-transport/src/finalmask/` → xmc/ 下 sleep 系只在 padding.rs:355-361,432,472（伪装流量形状的调度延时，非超时）。conn.rs 握手链 `read_varint_async`（:49-63）、`read_packet_async`（:66-82）内 `read_exact` 全部裸 await；`tcp_bridge` 握手失败 `Err(_) => return`（conn.rs:304）静默退出。
- 上层无兜底：`apply_tcpmasks`（finalmask/mod.rs:336）是**同步 fn**，仅链式包装，不可能注入异步超时。
- Go 侧原文核实：`deadline.go:9` `const handshakeTimeout = 2 * time.Minute`；`server.go:54-57` `beginHandshake()/defer endHandshake()` 包住整个握手；`client.go:78-81` 同；`deadline.go:24-41` 实现内部 handshake deadline 与 user deadline 取早（`earlierDeadline`，:69-76）。

**裁决：修正（实质证实）**。「Rust xmc 握手无超时、Go 2min」成立；引用位置错误。
**安全影响**：静默对端每连接钉死一个 tokio task + 2×8KB duplex 缓冲，直到对端主动断或内核报错——慢速探测下资源驻留无上界（Go 2min 兜底）。建议 P2。

### 声明 2 —— login-profile 白名单缺失（单因子 vs 双因子）【修正：实质证实】

**独立验证方法**：读 Rust `xmc/mod.rs` 全文（Config 字段）+ `conn.rs:150-230 raw`（签名与读包段）；Go 侧 grep `findProfile` 全目录定位后读 `server.go:59-133` 与 `:134-253` 原文核对顺序。

- Rust `xmc/mod.rs:30-44`：`Config` 字段 = `usernames / password / rsa_private_key / rsa_public_key / hostname / padding_disabled`——**无 profiles 字段**。
- `conn.rs:176-184`：`server_handshake(raw, rsa_private_key_der, rsa_public_key_der, password)` 签名无 profiles 参数；`conn.rs:212-213` `let _username = protocol::read_string(...)` / `let _uuid = protocol::read_uuid(...)` 读入即弃（下划线绑定）。密码即唯一因子。
- Go：`server.go:145` `profile, found := findProfile(c.profiles, string(username), uuid)`（profile.go:40-44 按 Username+UUID 精确匹配）；`server.go:219-222` `subtle.ConstantTimeCompare` 校验 password；**密码通过后** `server.go:223-227` `if !found` → 回 `"You are not white-listed on this server!"` Disconnect 并断连。= 双因子（password ∧ username+UUID 白名单）。

**裁决：修正（实质证实）**。行号修正：Rust 204-206 → 211-213；Go 228-233 → 223-227（findProfile 调用点 145）。
**补充**：Go 白名单命中后还回 Login Finished(0x02)（含 profile.TexturesValue/Signature，server.go:229-236），Rust 完全无此包（见声明 3 备注与新增观察 N2）——伪装保真同族缺口。

### 声明 4 —— RSA-1024 确定性派生 → 离线字典最优、时序侧信道冗余【证实】

**独立验证方法**：按契约只验三项前提事实（确定性派生 / 明文下发 / 比较短路），逐项读原文；利用性计算论证接受为前提不复算。

- **确定性派生**：`derivation.rs:129-151` `pub fn derive_rsa_key(password: &str)`（声明引用 129-152 **精确**）——seed = password 字节（:130），p/q 素数分别来自 `Sha256Stream(password‖"-p-prime")` / `(password‖"-q-prime")`（:131-138），`RsaPrivateKey::from_p_q`（:150）。测试实锤：`deterministic_derivation`（:162-167，同 password 同 n+d）、`different_password_yields_different_keys`（:171-175）、`modulus_is_1024_bit`（:179-183）。
- **生产接线**：`finalmask/mod.rs:1499` `build_xmc_config` 内 `let private_key = xmc::derivation::derive_rsa_key(password)`——服务端密钥对确实由 password 派生（非独立配置面），攻击模型前提成立。
- **公钥明文下发**：`conn.rs:219-224` Encryption Request 组包（serverId=""，公钥，verify_token，shouldAuth=1），`:221` `protocol::write_bytes(&mut p, rsa_public_key_der)` 明文上线。声明引用 216-217 实为 verify_token 生成（:216-217），公钥写入在 :221（+4 行漂移）。
- **比较短路**：`conn.rs:253` `if received_pw != password.as_bytes()`——普通切片比较，首字节失配即返回（非常量时间）；Go 对照 `server.go:219` 用 `subtle.ConstantTimeCompare`（常量时间）。

**裁决：证实**。三前提全部实锤；每 guess 本地派生无网络往返的推导结构成立（一次连接抓公钥 → 离线 guess→derive→比 n）。
**备注**：Rust 非 CT 比较 vs Go CT 比较本身是 Go 对齐缺口；在「公钥可离线碰撞」前提下把时序侧信道定级为冗余（可利用性≈0）自洽。

### 声明 6 —— shared secret 长度检查次序偏差【证实】

**独立验证方法**：Rust 读 `conn.rs:230-300 raw` 逐行编数；Go 读 `server.go:134-253` + grep 锚定行号。

- Rust 顺序：RSA 解密 shared（:239-241）→ RSA 解密 verify（:242-244）→ verify 前 4B 校验（:247-249）→ password 比较（:251-258）→ **shared 长度检查（:260-265，声明引用精确）** → 拷入 `[u8;16]`（:266-267）。
- Go 顺序：解密 shared（server.go:186-192）→ **长度检查（:193-195，`bad shared secret length`）** → 解密 verify（:197）→ verify 校验 → CT password（:219）→ profile（:223）。即 Go 在 verify token 解密**之前**查长度，与声明一致。

**裁决：证实**——次序偏差存在且引用精确；「无安全后果」就保密性/完整性成立：shared_secret 在长度检查前未参与任何密码学运算或内存拷贝，PKCS1v15 解密输出长度有界（≤128B，Vec 承载无溢出面），定长拷贝 gated 在检查之后。
**精确化备注**：错误路径次序差异制造一个低价值探测分流点——「畸形长度 shared secret + 错密码」组合下 Go 在 ：193 静默断（无 Disconnect），Rust 先回 `authservers_down` Disconnect（:256）再断；与声明 3 同族但需攻击者主动 RSA 构造畸形密文，信号价值远低于声明 3。不改变原判。
