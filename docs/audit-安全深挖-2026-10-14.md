### 1.3 可利用性定量论证（纯计算，未做动态实验——明标）

**信号**（每候选 guess 一次握手测量）：
Rust `[u8] != [u8]` 短路于首差异位置 pos：测量时间差 δ ≈ ceil(pos/字宽) × 1-4 cycles + 函数调用差 ≈ **10-100 ns**（16-32B 密码全量程；即便放大大到 1 μs 不改变结论）。

**噪声**（端到端握手墙钟，攻击者在 WAN 可观测的全部方差）：
- 网络：us1 RTT ≈ 169 ms（项目记忆量级），跨洋抖动 σ_net ≈ **1-10 ms**，分钟级 regime 摆动更大（项目历史实证单流 0.05↔7 MB/s 分钟级摆动）；
- 服务端 2×RSA-1024 CRT 解密（无 blinding）：每次 0.2-1 ms，数据相关方差（Marvin 面）≈ **10 μs-1 ms**；
- tokio 调度 + syscall 唤醒：≈ **1-100 μs**。
→ 主导噪声 σ ≈ **10⁶-10⁷ ns**；信号噪声比 δ/σ ≈ **10⁻⁴ ~ 10⁻⁵**。

**样本复杂度**：N 次独立测量平均后 σ/√N；区分两个候选需 5σ 分离 →
N ≈ (5σ/δ)² = (5×10⁶/10²)² ≈ **2.5×10⁹ 样本/二元判定**（WAN，σ=1ms、δ=100ns）。
每样本 = 1 条 TCP 连接 + 完整 MC 握手 ≥ 2×RTT ≈ 0.34 s（协议每连接只允许 1 个 guess——verify token 一次性往返）。
→ 每个二元判定 ≈ 2.5×10⁹ × 0.34 s ≈ **2.7×10⁷ 年**；逐字节前缀攻击 × 密码长度 × 候选字符集 → **≥10⁹-10¹⁰ 年量级，天文不可行**。
即便把攻击者搬到同机房（σ≈10 μs 由 RSA 噪声托底）：N ≈ (5×10⁴/10²)² = 2.5×10⁵ 样本 × ~1 ms ≈ 分钟级——但该威胁模型下时序攻击才刚刚可行，而 finalmask 是 WAN 传输伪装层，本就不设防同址攻击者（Go 的恒时实现在同址也不泄露——这正是差距所在，但修复收益仅限这一小威胁模型）。

**占优通道（终局论据）**：RSA-1024 密钥对由 password **确定性派生**（derivation.rs:129-152，`sha256Stream(password‖"-p-prime"/"-q-prime")` → 素数 → n；Go derivation.go 逐字节同构），且公钥 (n,e) 在 Encryption Request **明文下发**（conn.rs:216-217 / server.go:159）。攻击者恢复密码的最优路径是**离线字典碰撞**：guess → derive_rsa_key(guess) → 比较 n。每 guess = 2×derivePrime（SHA256 流 + Miller-Rabin 20 轮 + 递增搜索）≈ 1-10 ms/核 → **10²-10³ guess/s/核，零网络痕迹、无任何限速、完全可并行**；命中即同时获得完整客户端伪装身份。此通道严格占优时序通道（快 ≥10¹⁰ 倍且无噪声问题），攻击者**永远不需要**时序预言机。密码安全性实质 = password 熵（R1 R14-SEC-014 已在案）。

**定谳**：R14-SEC-001 的"代码级 Go 安全降级（CWE-208）"定性成立、修复应做（成本 ~2 行）；但"真实时序口令预言机面"的 P1 表述过重——远程可利用性 ≈ 0（差 4-5 个数量级 + 每连接限速），且存在完全占优的离线通道使预言机冗余。**建议 PM 裁定 P1→P2**（Go 对齐 + 纵深防御档），安全实质瓶颈在 password 熵（SEC-014，协议固有）。

### 1.4 修复方案（API 级，供 fullstack 派单；本轮不实施）

**依赖**：`subtle` 2.6.1 已在 Cargo.lock:4175-4179（传递依赖），`crates/xray-transport/Cargo.toml` [dependencies] 增 `subtle = { version = "2", default-features = false }` —— **不新增 lockfile 条目**。

**conn.rs:252-253 替换**：
```rust
use subtle::ConstantTimeEq;
let received_pw = &decrypted_verify[4..];
if !bool::from(received_pw.ct_eq(password.as_bytes())) {
    // 原 disconnect(authservers_down) + "bad password" 保持不变
}
```

**len 不等语义陷阱**：`<[u8] as ConstantTimeEq>::ct_eq` 实现为 `self.len() == other.len() && 逐字节恒时 OR`——长度不等**立即返回 Choice(0)，长度不恒时**。Go `subtle.ConstantTimeCompare` 完全同构（源码首行 `if len(x) != len(y) { return 0 }`）。故该修法与 Go 逐语义一致，**不引入 Go 没有的行为**。长度泄露敏感性：攻击者可控 guess 长度，len 失配跳过扫描理论上可分辨"我猜中了长度"——泄露的是 password **长度**（非内容），量级同 10-100 ns 被网络噪声淹没，且 Go 上游接受同一语义；若要连长度都藏需定长 padding，偏离 Go 且无实益，**不做**。注意 `bool::from(Choice)` 消费 Choice，`ct_eq` 参数用 `&[u8]` 借用即可，无分配。

**单测设计**（语义锁；恒时性本身不做 CI 断言——无 dudect 基建，时间断言在 CI 上必然 flaky，注释说明）：
```rust
#[test]
fn password_compare_semantics() {
    let f = |a: &[u8], b: &[u8]| bool::from(a.ct_eq(b));
    assert!(f(b"secret", b"secret"));    // 全等
    assert!(!f(b"secret", b"sekret"));   // 首字节差异
    assert!(!f(b"secret", b"secreT"));   // 末字节差异
    assert!(!f(b"secret", b"secret1"));  // 长度 +1（Choice(0)，不 panic）
    assert!(!f(b"secret1", b"secret"));  // 长度 -1
    assert!(f(b"", b""));                // 空对空（Go ConstantTimeCompare("","")==1 同语义）
    assert!(!f(b"", b"x"));
}
```
外加握手级回归：错密码 → authservers_down disconnect 路径不变（既有 e2e 覆盖）。

**随单建议一并派**：① `tcp_bridge` 握手段包 `tokio::time::timeout(HANDSHAKE_TIMEOUT, ...)`（对齐 Go 2min，常量同名）；② profile 白名单补齐（Config 增 profiles + 密码通过后校验，回 Go 同款 not-white-listed 文案）——两项均为 Go 已有缓解的 Rust 缺口，属本深挖新发现，当前不在任何 bd 票上。

### 3.3 wire/client 层（client.go 441 行 vs client.rs 393 行）

逐项一致（**全部 ✓**）：三形态编码——poll 17B（`data[8]=8`+8B 随机）/small ≤cap-12（`data[8]=3`+3B 随机）/frag ≤255×(cap-15)（`data[8]=3|0xC0`+fragID/idx/n@12/13/14）；clientID 随机 8B 且 `[0]&=0xFC`；响应解帧 `[len2|0xC0]` 含 Go 的 **len 超界清空全部帧 quirk**（client.rs:159-176 vs client.go:159-172 逐行同构）；resolver least-sends 轮转（`sends[index].Add(1)` 后仍用 index 发送，两实现同 quirks）；DNS ID 随机化（Go pack 后覆写 pack[:2] / Rust 构造时随机——client.rs:258 注释明示等价）；extraPoll 追加空 poll；pacing 500ms×2→10s 上限；`WriteTo` 0/>4096 拒绝；发送队列满**丢弃但报成功**（Go select default / Rust try_send 丢弃——同 quirk）。

**偏差（2 处，非 wire 破坏）**：① Go recv 错误 → 该 resolver 的 goroutine **退出**（client.go:247-252，出错 resolver 永久瘫痪）；Rust `Err(_) => continue` 永续重试（client.rs:225）——Rust 更健壮，行为可观测差异。② 随机源 Go `mrand.Intn` / Rust `next_u32() % n` 模偏差（微小，非安全敏感——domain/qtype 选择仅影响伪装形态分布）。

### 3.4 domain 层（domain.go 215 行 vs domain.rs 268 行）

校验阶梯逐项一致（**全部 ✓**）：`..` 拒 / lenLimit ≤255 / labelLimit ≤63 / types ∈{A,CNAME,TXT,AAAA}（domain.rs:24-33 type_map 报 "unknown types"）/ edns0 ∈ {0}∪[512,4096] / `lenLimit ≥ name.Length+1` / cap≥17 拒；cap/lenMax 公式**逐字符同式**（`n=(L-name-1)/(label+1)`、`total=n·label+(left>1)(left-1)`、`cap=DecodedLen(total)=total·5/8`、`lenMax=name+1+EncodedLen(cap)+...`，domain.rs:104-120 vs domain.go:104-117）；IsDomain 大小写不敏感严格后缀（domain.rs:131-142）；Encode base32 小写切 label（Go >254 panic / Rust `Name::new` 报错——等价 fail-closed，调用路径由 cap 保证不触达，domain.rs:158 注释明示）；Decode 失败返空。cap 公式有单测锚定 Go 测试值（domain.rs:249-256，cap=57）。

### 3.5 server 层（server.go 385 行 vs server.rs 411 行）+ frag + resp

**校验阶梯逐级对齐（全部 ✓）**：unpack 失败静默丢 → Response 丢 → OpCode≠0 → NOTIMPLEMENTED → 单 question→FORMERR → OPT 重复→FORMERR → OPT 版本≠0 → SUCCESS+`TTL=1<<24` → edns0 clamp[512,4096] → 域名 miss→NAMEERROR → type/`n<9`/形态校验（`decoded[0]&3` ↔ qtype、`decoded[8]&0x3F∈{3,8}`、small n≥13、poll n==17）→ SUCCESS+AA → recCh(255) 满 → SUCCESS+AA → poll 早退 / frag Feed / small 直取 → `readCh` 投递 addr=fd::/8 派生（server.rs:74-83 与 Go ClientID.Addr 同构）。SendManager（stash cap1 / ch cap128 / TTL 4s / Pop 缺省建档 / Push·Stash 满丢）/ send 攒包（left=resp.cap、`left<0` stash 回、末帧 `|0xC000`）/ FragManager（TTL 8s、单 entry 4096、**per-client 16384 且末片豁免**（frag.rs:132-134 `filled < total-1` 与 Go frag.go:145-147 同）、4096 entries、tryRemove 驱逐最旧）/ Resp 容量四式（A `3n-1`、CNAME `cap·n-n-1`、TXT `255n-n+(m>1)(m-1)`、AAAA `15n-1`，`size=min(max(edns0,512),max(domain.edns0,512))`、OPT 开销 11）/ Encode 四形态（A/AAAA `[i,fragN,payload]`、CNAME 经 domain.Encode、TXT 单 RR 多 string、TTL 60、OPT echo）/ Decode（TXT 严格界检、frags 按 `f[0]` 排序 + `frags[0][1]≤len` + 相邻去重、CNAME 解压归一化后 domain.Decode）——**逐语义一致**。

**已声明偏差**：server send 攒包 pacing（Go `timer.Reset(0)` 与就绪 channel 随机竞争会随机提前截断；Rust 确定性排空，server.rs:226-228 注释）——wire 合法仅 pacing 差异，commit+代码双处声明，接受。**新记录（边角）**：Go `ClientIDFromAddr` 对 4 字节 IPv4 会 `IP[8:]` 越界 panic（server.go:378-380）；Rust `client_id_from_addr` V4 返 `[0u8;8]`（server.rs:86-94）——Rust 更稳，行为偏差注记。

**潜在隐患注记（当前不可达）**：resp.rs:53 `edns0.max(512) as i16`——u16>32767 会负溢出使容量为负；但两条调用路径 edns0 均 ≤4096（server 侧 server.rs:189 clamp 后传入 + domain.edns0 经 Domain::new 校验），client 侧恒 0（client.rs:169）。不可达，建议 fullstack 顺手 `as isize` 消除埋雷，非漏洞。

### 3.7 零不一致声明 + fuzz 用例建议

**wire 层（proto + 五层协议机）零不一致实证声明**：client 三形态编码/解帧、server 校验阶梯、FragManager、SendManager、Resp 容量与编解码、Domain 容量模型——全部逐语义一致（含 3 个 Go quirk 的保真复制）。全部不一致集中于 **conf/JSON 接受面（D1-D5）与解析严格度（D6）**，无一影响双端已对齐配置下的 wire 互通。

fuzz 建议（现有 targets：vless_inbound/ss2022_packet/kcp_segment，按优先级）：
1. **`xdns_wire_message`**：`message_from_wire_format` 全输入（header 计数矩阵 × 指针链自指/越界 × 保留 label type × CNAME 嵌套指针）——断言无 panic、Err 或不变量成立。
2. **`xdns_server_read`**：随机 flags/OpCode/questions/OPT-Additionals × 域名后缀命中 × `decoded[8]` 形态位 ∈{0,3,8,3|0xC0,随机} × frag 序列——断言无 panic + FragManager 不变量（entry ≤4096、sizem ≤16384、m ≤4096）。
3. **`xdns_resp_decode`**：随机 answer 段（四 qtype 混合、重复 frag idx、`frags[0][1]` 谎报、帧 len 超界）——断言无 panic、负例返空。
4. **`xmc_server_handshake`**：随机包序列（varint 5B 边界、packet 长度下溢/超 32KB、RSA 垃圾密文、verify token 错位、密码含 0x00）——断言 io::Error 收敛无 panic。
