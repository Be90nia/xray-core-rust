### 3.1 P1 组

#### AUDIT-PERF-001 trait Reader/Writer 返回 Pin<Box<dyn Future>>——dyn-compatible 装箱税（bd xi40 第 4 条）

- **crate / 文件:行号**：`xray-buf/src/io.rs:73-79`（Reader）+ `:98-110`（Writer）+ `:108-110`（shutdown_flush）
- **证据**：
  ```rust
  pub trait Reader: Send {
      fn read_multi_buffer(
          &mut self,
      ) -> Pin<Box<dyn Future<Output = Result<MultiBuffer>> + Send + '_>>;
  }
  ```
  → trait 内 65+ 处 `Box::pin(async move { ... })`（grep `Pin<Box<dyn Future` 计），每次调用 = 1 次堆分配（4.5KB-8KB 量级）。decorator 链（stats.rs / endpoint_override.rs / timeout.rs / readv.rs / reader.rs / writer.rs / pipe.rs / dialer.rs 等）每层 × 每读 = N 倍放大。
- **影响**：每次数据面读/写 = 1+ 次堆分配。装饰链 3 层 × 1 alloc/层 = 3 次/读。P1 收口后实测 `alloc/MB` 字节口径 <5% 且 loopback 无差（baseline.md §3 P1 R4：alloc 次数 server -12.0%、client -33.7% 但**剩余次数**即所列 trait 装箱）；alloc 次数大头即本项。
- **建议**：trait 改 RPITIT（`async fn`/`impl Future`）或 poll 化（`fn poll_read(&mut self, cx: &mut Context, dst: &mut MultiBuffer) -> Poll<...>` + 具名 future 默认方法）。ARCHITECTURE.md §1.2 §6 标为【规划 P1】，已被 `d820547f` 全家回退到 `547200b3` 基线——在 feature/framework（f242e67b）分支重做。
- **风险**：大面积签名变更，波及所有 Reader/Writer 实现（xray-buf / xray-tls / xray-reality / xray-mux / xray-app-dispatcher / xray-crypto / xray-proxy-*）；建议先在 bridge 泵热点路径做 poll 化试点——**注意 bridge 泵有 `378ab889` 回档史**（per §0.1），须同 binary 同窗交替 A/B。
- **优先级**：P1——已知 trait 层积压，bytes/MiB 主要落在所列 trait 调用方；切到 RPITIT 后 alloc 次数可再降 -20% 量级（机理：移除 Box::pin 一次 heap + 移除 future 大小分歧一次 heap）。

#### AUDIT-PERF-002 mux 帧 meta 每 path 1-2 次小堆分配

- **crate / 文件:行号**：`xray-mux/src/frame.rs:528-547`（write_meta_to）+ `:602-604`（read_meta）+ `xray-mux/src/writer.rs:128-130`（write_meta_only）+ `:502-503`（meta_buf 每帧 alloc）+ `xray-mux/src/client.rs:693-700`（read_frame body）+ `xray-mux/src/worker.rs:889-892`
- **证据**（frame.rs:528-547 + writer.rs:128-130）：
  ```rust
  pub fn write_meta_to(&self, ...) -> io::Result<Vec<u8>> {
      let mut buf = Vec::with_capacity(64);  // 每帧 alloc
      // ... serialize ...
      Ok(buf)
  }
  // writer.rs:128:
  pub async fn write_meta_only(&mut self, meta: &FrameMetadata) -> io::Result<()> {
      let meta_bytes = meta.write_meta_to(...);  // 每帧 alloc 1
      ...
  }
  ```
  mux 协议帧含 `<u16 len><meta body>`（≤274B）。每帧（数据帧 + End + KeepAlive）调一次 `write_meta_to` = 1 alloc + serialize + write_all = 2 拷。
- **影响**：mux 开启用户每连接每秒数千帧（8KB 帧约 1.5 万/方向，1Gbps），meta 累积分配对 alloc/MB 是显著贡献。`h6p5` 票面已知残留。
- **建议**：meta 写入走调用方 scratch（u16 len + ≤274B 体积可栈上 `SmallVec<[u8; 64]>` 或调用方 `Vec` 复用）；读侧 body 帧已部分池化（28bce568），meta 路径仍残留。
- **风险**：wire 不变；bd txhn 帧原子性语义（整帧单次落盘）不得破坏。

#### AUDIT-PERF-003 SS UDP 每 datapacket 多次 to_vec

- **crate / 文件:行号**：`xray-proxy-ss/src/ss2022/packet.rs:238, 270, 392, 758` + `xray-proxy-ss/src/config.rs:215-249` + `xray-proxy-ss/src/protocol.rs:216-224, 233-234, 303-371`
- **证据**（ss2022/packet.rs 多处）：
  ```rust
  // 每 UDP 包：
  let plaintext: Vec<u8> = buf[iv_len..].to_vec();              // 拷 1
  let zero_nonce = vec![0u8; aead.nonce_size()];              // alloc 1（nonce 12B 固定）
  let sealed = aead.seal(&zero_nonce, &[], &plaintext)         // 拷
                  .map_err(...)?;
  // 解码：
  let ciphertext: Vec<u8> = buf[iv_len..].to_vec();            // 拷 1
  let zero_nonce = vec![0u8; aead.nonce_size()];              // alloc 1
  let plaintext = aead.open(&zero_nonce, &[], &ciphertext)    // 拷
  ```
  每包 3 次 alloc + 2 次全量拷贝（plaintext/ciphertext）+ 1 次 nonce alloc。
- **影响**：SS2022 UDP 高频小包（DNS 查询 ~100B）每包 ~2KB alloc；每秒 1000 包 = 2MB alloc 流量，全在 mimalloc 下也是锁争用。
- **建议**：解码借用切片返回 range；encode 复用 frame scratch（注意 chacha_plain 字段所有权）；nonce 改 `[u8; 12]/[u8; 24]` 栈上固定数组（按 cipher 派生 const）。
- **风险**：wire 不变；SS2022 重放窗口逻辑勿动（已在 bd 票面登记）。

#### AUDIT-PERF-004 CachedReader sniff 整包 `to_vec`（bd xi40 第 2 条未修）

- **crate / 文件:行号**：`xray-app-dispatcher/src/default.rs:1520-1544`（CachedReader）+ `xray-app-dispatcher/src/sniffer.rs:740-830`（QUIC HP 解密 + to_vec）
- **证据**（default.rs:1524）：
  ```rust
  fn cached_bytes(&self) -> Vec<u8> {
      self.cache.as_ref().map(|mb| mb.to_vec()) // ← xi40 第 2 条残留
  }
  ```
  + `sniffer.rs:798` `let mut packet_buf = payload.to_vec();` + `sniffer.rs:830` `let aad_data = packet_buf[..ext_hdr_len].to_vec();`。
- **影响**：嗅探时整包 flatten 拷贝（每连接 1-2 次，非每帧），低收益但仍 alloc；QUIC HP 解密必须 mutable copy（ring open_in_place 前置变换，clippy.toml 已白名单注释明示）。
- **建议**：sniff 各 sniffer 直接迭代 `mb.iter()` 切片免 flatten；QUIC HP 的双 to_vec 是 `open_in_place` 前置变换（算法固有），但 `aad_data` 的拷贝可借 `&packet_buf[..ext_hdr_len]`（aad 不需要 owned），skip 是已审查的「算法固有」。
